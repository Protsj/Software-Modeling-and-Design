# Store Automation System

Це навчальний проєкт, розроблений в рамках курсу "Моделювання та проєктування програмного забезпечення". 
Проєкт демонструє класичну N-рівневу архітектуру для системи автоматизації роботи продуктового магазину.

## Що було реалізовано:

1. **Реляційна модель даних (Завдання 1)**
   Спроектовано 5 взаємопов'язаних таблиць з використанням різних типів зв'язків:
   - `Categories` (Категорії товарів)
   - `Products` (Товари) - Зв'язок 1:N з `Categories`
   - `ProductInfo` (Детальна специфікація) - Зв'язок 1:1 з `Products`
   - `Receipts` (Чеки/Замовлення)
   - `ReceiptItems` (Позиції в чеках) - Зв'язок N:M між `Receipts` та `Products`

2. **Об'єктно-орієнтована модель (Завдання 2)**
   Створено C# класи, які відповідають структурі спроєктованих таблиць. Реалізовано композицію об'єктів (відношення "ціле-частина"): клас `Product` повністю володіє своїм `ProductInfo`, а `Receipt` приховує всередині список `ReceiptItem`, інкапсулюючи логіку додавання нових позицій.

3. **Сховище даних / Репозиторій (Завдання 3)**
   Реалізовано клас `StoreRepository`, який відповідає за імітацію роботи бази даних в оперативній пам'яті (In-Memory Database). Клас містить усі необхідні CRUD-операції (Create, Read, Update, Delete) для кореневих сутностей, з урахуванням роботи посилальних типів даних (Reference Types). Створено тестові дані (`MockData`) для наповнення сховища.

4. **Бізнес-логіка та Модель прецедентів (Лабораторна 3)**
   Реалізовано клас `StoreService`, який перетворює UML-діаграму прецедентів на реальний код:
   - Обслуговує процеси Касира: `OpenNewReceipt`, `ScanProductToReceipt` (з перевіркою залишків товару на складі), `CloseReceipt`.
   - Обслуговує процеси Адміністратора: `AddNewProduct`, `PrintAllReceiptsDetails` та `PrintFullProductInfo`.

5. **Наскрізна функціональність (Лабораторна 4)**
   Впроваджено архітектурні вимоги згідно з Додатковою специфікацією:
   - **Безпека (RBAC):** Створено `SecurityManager` для авторизації та розмежування прав доступу на основі ролей (`None`, `Cashier`, `Admin`). Усі методи бізнес-логіки захищені від несанкціонованого доступу.
   - **Структуроване логування:** Інтегровано пакет `Serilog`. Створено централізований клас `Logger`, який адаптується під середовище розгортання: забезпечує кольоровий консольний вивід для локальної розробки та вивід у форматі JSON для інтеграції з Docker.

## Структура проєкту

Реалізовано розподіл коду згідно з принципами SOLID (Single Responsibility):
- `/Models` - класи структури даних (сутності бази даних).
- `/Repositories` - логіка доступу до даних (`StoreRepository`).
- `/Data` - ініціалізація початкових тестових даних (`MockData`).
- `/Services` - бізнес-логіка та наскрізна функціональність:
  - `StoreService.cs` - реалізація прецедентів системи.
  - `SecurityManager.cs` - управління сеансами та перевірка ролей користувачів.
  - `Logger.cs` - налаштування Serilog та структурованого логування подій і помилок.
- `Program.cs` - точка входу в програму (Main), де описано демонстраційний сценарій роботи різних акторів.
- `StoreAutomatization.csproj` - конфігурація проєкту та підключених NuGet-пакетів.
