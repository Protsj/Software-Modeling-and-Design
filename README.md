# Store Automation System

Це навчальний проєкт, розроблений в рамках курсу "Моделювання та проєктування програмного забезпечення". 
Проєкт демонструє класичну N-рівневу архітектуру для системи автоматизації роботи продуктового магазину.

## Що було реалізовано:

1. **Реляційна модель даних (Завдання 1)**
   Спроектовано 5 взаємопов'язаних таблиць з використанням різних типів зв'язків:
   - `Categories` (Категорії товарів)
   - `Products` (Товари) - Зв'язок 1:N з `Categories`
   - `ProductInfo` (Детальна специфікація) - Зв'язок 1:1 з `Products`
   - `Receipts` (Чеки/Замовлення)
   - `ReceiptItems` (Позиції в чеках) - Зв'язок N:M між `Receipts` та `Products`

2. **Моделі об'єктів (Завдання 2)**
   Створено C# класи, які відповідають структурі спроєктованих таблиць. Реалізовано "чисті" моделі (POCO) без навігаційних властивостей для кращого розуміння ручного з'єднання даних (JOIN).

3. **Сховище даних / Репозиторій (Завдання 3)**
   Реалізовано клас `StoreRepository`, який відповідає за імітацію роботи бази даних в оперативній пам'яті (In-Memory Database). Клас містить усі необхідні CRUD-операції (Create, Read, Update, Delete) для кожної з моделей. Створено тестові дані (`MockData`) для наповнення сховища.

4. **Сервіс бізнес-логіки (Завдання 4)**
   Реалізовано клас `StoreService`, який:
   - Відповідає за бізнес-логіку програми.
   - Отримує дані через ін'єкцію залежностей від `StoreRepository`.
   - Виконує ручне з'єднання даних (JOIN) на рівні коду.
   - Форматує та виводить консольні звіти: детальний каталог товарів та розгорнуту історію чеків.

## Структура проєкту

Реалізовано розподіл коду згідно з принципами SOLID (Single Responsibility):
- `/Models` - класи структури даних.
- `/Repositories` - логіка доступу до даних (`StoreRepository`).
- `/Data` - ініціалізація початкових даних (`MockData`).
- `/Services` - бізнес-логіка та обробка інформації (`StoreService`).
- `Program.cs` - точка входу в програму (Main).
